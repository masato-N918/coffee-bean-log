# 非機能要件：coffee-bean-log

> 中央ドキュメント：[要件定義書.md](要件定義書.md)

| 分類 | 項目 | 要件 |
|------|------|------|
| 性能 | 操作の反応 | 一覧の表示・絞り込み・並び替え・保存などの操作は、体感で待たずに反映される（目安1秒以内） |
| 性能 | 想定データ量 | 個人利用の範囲（目安：豆は数百件、抽出記録は数千件）で快適に動作する |
| 可用性 | 動作環境 | 自分の PC（ローカル）と AWS（EC2 1台 + RDS for MySQL）で動作する |
| 可用性 | 稼働時間・冗長化 | 常時稼働はしない。動作確認・スクリーンショット撮影のときだけ構築する。冗長化（複数台構成など）は対象外 |
| 対応環境 | 対応ブラウザ | PC・スマートフォンのモダンブラウザ最新版（Chrome / Safari / Edge） |
| 対応環境 | 画面サイズ | PC とスマートフォンの両方で使えるよう、レスポンシブ対応する |
| データ | 永続化 | リロードしても消えない。MySQL に保存する |
| データ | バックアップ | 必須としない（学習用途のため）。AWS 環境を削除すると DB のデータも消える |
| ユーザビリティ | 手軽な記録 | 抽出記録は入力項目を「基本」と「詳細（任意・折りたたみ）」に分け、コーヒーマシンの人でも少ない入力で記録できる |
| ユーザビリティ | 分かりやすい表示 | 焙煎度は「シティ（中深煎り）」のように、一般的な呼び方を添えて表示する |
| ユーザビリティ | 誤操作防止 | 豆・抽出記録の削除は確認のうえ実行する。豆の削除時は、抽出記録も消えることを伝える |
| ユーザビリティ | 入力チェック | 必須項目・文字数・数値の範囲を、フロントエンドとバックエンドの両方でチェックする |
| ユーザビリティ | エラー表示 | 入力エラーや通信エラーは、画面上に日本語で表示する |
| 保守性 | コード | 学習目的として、機能ごとに整理された読みやすい構成とする |
| セキュリティ | 認証 | MVP では認証なし（ログインは将来拡張） |
| セキュリティ | 秘密情報 | DB のパスワードなどは Git に含めない |
| 運用 | 費用 | 使うときだけ環境を構築し、使い終わったら `terraform destroy` で削除して、費用を最小限に抑える |
| 運用 | 構築 | インフラは Terraform でコード化し、何度作っても同じ環境になるようにする |
